# Pipeline declaration

Every model call and every host step on the served path, with the lines that show them.
No model weights or opaque components; the only model is hosted and called over HTTP.
Stages (R1, P, A1, …) are in §3, host mechanisms M1–M64 in §4.

## 2. Served path

### 2.1 Entry

- `Dockerfile:8` starts `app.main:app`, one worker. `POST /seed` stores the user's pairs, subjects and links and embeds the pairs (M20; `app/main.py:46-58`). `POST /run` calls `CaseRunner.run` (`app/main.py:60-72`); an invalid body gets 400, a failed run 500, with the error text; bodies are ASCII JSON.
- SQLite store; every pair, subject, link and vector row is keyed by the user id (`app/store.py:11-51`). Of the request the host reads the case id, `system_prompt`, the message, the catalog, the tool endpoint, the user id and the relay URL (`app/protocol.py:25-32`); the case id goes only into tool endpoint bodies (`app/tools.py:146`) and logs. 285 s case deadline, one tool executor per case (`app/agent.py:111-115`).

### 2.2 Lane

Without a model the host ranks the user's stored conversations (`app/memory/retrieval.py:345-444`), finds the identifier focus (M7) and the request kinds (M52), and classifies the main clause (M44) with the catalog's tool names (M4) (`app/agent.py:118-126`). The first rule that holds moves an action-lane request to the records lane (`app/agent.py:127-138`):

| reason | when |
|---|---|
| `identifier` | lane reason `live`, and an identifier focus |
| `identifier-held` | an identifier focus, and AT with its fetching test read per sentence |
| `own-records` | reason `live`; asks, names nothing to be done, no outside source, no capitalised name the store lacks; a name, address, code or quoted phrase of it, or the noun of "my/our <noun>", is in the store (`app/lane.py:347-391`) |
| `identifier-read` | reason `default`; AT with "work" as a reading verb (`app/lane.py:38`); an identifier or hyphenated code (`app/store.py:54`) a ranked record holds (`app/packet.py:77-79`) |
| `topic` | no kind, no identifier focus, AT, a topic the store dwells on (M27) |
| `quoted` | no kind, AT, quoted words the store holds (`app/memory/retrieval.py:220-223`) |

A records-lane request with a kind is decided on the action lane, reason `guided` (M53, `app/agent.py:139-140`). The lane picks prompt and packet; every turn that may call tools gets the whole catalog (M3).

AT, the asking test (M25, `app/lane.py:405-410`): the request asks (a question, also by a later clause opening with a question word and a helper verb; or a reading or speech verb such as list, find, tell, name, give, spell, walk; or "put … in order"; or "add up …" with a "?", no figure but dates and no outside source; or a last sentence with "then" ending ", please" and holding no verb of doing or reading; `app/lane.py:183-194`, `app/lane.py:423-437`), has no verb of doing (send, set, update, schedule, create, delete…; a "put … in order" or such an "add up …" part is not one; `app/lane.py:455-464`), names no outside source (web, online, internet, news, google, browse, "look it up"; `app/lane.py:64`), names no listed tool in full (memory tools, one-word and all-generic names aside; `app/lane.py:224-232`), and does not pair a fetching verb with a word of a listed non-memory reading tool's name, same word, singular or plural, or for 5+ letters and not a common word one edit away (`app/lane.py:440-452`); with an identifier focus only within one sentence (`app/lane.py:400-402`).

### 2.3 Records lane

- Short paths first, only for a request passing AT and not of reason `statement` (`app/agent.py:78-95`): P (M26) when the focus passes `short_records` and has a focus token; with no focus, the topic path (M27); M46. A short path ending with reply text answers; else its calls go on (M54).
- Stages (`app/records.py:421-459`): R1; the packet (M7) with meaning order (M20; `app/agent.py:144-153`); advisory blocks (M8); T or S, then N; the loop R3 with D/DC (M17), FQ, AC (M37), RA (M1); closing turn R4.

### 2.4 Action lane

Packet (M7) without embeddings, M34's block, catalog in route order (M4), M52's notes; A1/A2 with RC, DR, RR/RV, DK, RA (`app/agent.py:155-162`, `app/action.py:563-712`).

### 2.5 Response

- `final_text`: the text of the completion that ended the deciding loop, outer whitespace removed (`app/agent.py:172`); if R3's loop ends with no text, draft 1's when M17 ran (`app/records.py:611-612`). `answer`: the value after `ANSWER:` on its last line starting with it (M6; `app/records.py:613`, `app/action.py:711`). Both pass through M22 and M24, nothing else.
- `tool_calls`: calls that crossed to the tool endpoint and were not refused with a 4xx (M14). The wire body holds `final_text`, `tool_calls`, `prompt_tokens`, `output_tokens`, `latency_ms` and, when present, `answer` trimmed, nothing else (`app/protocol.py:51-61`).

## 3. Model calls

Common (`app/llm.py:242-337`):
- Sent to the request's relay URL, else the configured endpoint (`app/agent.py:68-72`, `app/llm.py:343-361`). Payload (`app/llm.py:243-256`): model, messages, `temperature` 0 and `seed` 42 unless a stage sets them (`app/config.py:42-43`), reasoning effort, `max_tokens`, and with tools `tool_choice` `auto` or the stage's; on the configured OpenRouter route (no relay URL) also `reasoning` with `exclude` and fixed `provider` preferences (`app/llm.py:153`). No `n`, no `best_of`. At most max(4, running cases) calls in flight (`app/llm.py:166-185`).
- Resent only after a transport failure or timeout, on 408/409/425/429/5xx, or for a 200 that is not a completion; 429, or 503 with `Retry-After`, waited out ≤5 s, ≤30 times; after a timeout `max_tokens` × 0.4, ≥1200; other statuses raise; `once` calls (D, DR) never resent (`app/llm.py:263-337`). A completion is returned as it came; text parts joined, a nameless call dropped and logged (`app/llm.py:126-134`). All usage, failed calls' too, enters the case tally (`app/action.py:94-101`).
- A model call is repeated to later turns as written, minus arguments with an empty name; endpoint and `tool_calls` get it unchanged (`app/action.py:351-355`). Effort is the lane's, `medium`, unless stated (`app/config.py:38-41`).

Text dropped. ## 4. Host mechanisms

- **M1 Identical calls** (`app/tools.py:112-140`): identity = name + arguments with sorted keys (`app/tools.py:64-65`). A call identical to one of this request that `completed` or has unknown delivery is posted only on RA's `SEND`; else held, its note as result, logged `blocked_before_execution`, not in `tool_calls`. For a read (name with a `READ_PREFIXES` prefix or `_search`; `app/lane.py:140-141`) only a completed earlier read counts, and only while no other call has completed or gone out with unknown delivery since.
- **M3 Catalog.** R1, R3/R4, DC, P, Q, FC and A1/A2 get the whole catalog every turn, `auto`, each tool as given (empty description: its name; no parameters: empty object schema; `app/tools.py:84-89`); the records lane adds `calculate` when no tool has that name and `find_in_records` on S's packets (`app/records.py:104-107`); only the action lane's order changes (`app/surface.py:36-66`, `app/route.py:322-324`). D: R3's list, `none`; DR: A1's list; S: `find_in_records`, `calculate`; O, SD, T, N, L, H, FQ, RA, RC, RR, RV, AC, DK: none.
- **M4 Lane choice** (`app/lane.py:296-344`). Clauses are read against action, framing and speech verbs, save and need forms and the catalog's tool-name words, reading and writing tools apart (`app/lane.py:147-159`); then live cues, arithmetic words with figures when `run_code` is listed, a tool named in full; cue and tool words match within one edit (`app/lane.py:162-175`), but a word written with a capital letter is a name, not a misspelt arithmetic word (`app/lane.py:90`). In a clause asking to put things in order, or to add up as in AT, its verb is not an action word, and for the latter "current" is no live cue (`app/lane.py:315-316`, `app/lane.py:324`, `app/lane.py:423-428`). Reasons `imperative`, `imperative-setter`, `read-capability`, `live`, `arithmetic`, `names-tool` give the action lane, but `stored-detail` (records) for the first four when the request asks for a contact detail the user keeps (email, address, phone, handle) with no write or send verb and no code-like identifier; a write verb right after "did/have/had" + "I/we" ("what handle did I save") asks back and is not one, nor one whose nearest subject before it in its part is I/we (no modal before, no you/please between): the user's own act ("before I send") (`app/lane.py:54-58`, `app/lane.py:235-267`). Otherwise `request` (action: "can/could/would/will you" or "have/get" + an action word, or a later part opening with one; `app/lane.py:277-288`), `statement` (records: asks nothing, speaks of the user, also after a lead-in of ≤4 words and a colon; `app/lane.py:96-117`), read as `asked` instead when a later sentence opens with a reading or speech verb, asks to put things in order or is AT's ", please" form (`app/lane.py:291-293`, `app/lane.py:337`), `question`, `asked`, `stored-detail` (records), else `default` (action). "do not/didn't …" openings are not questions by the first test, "remind me how long/many/much" is, and so is a later clause opening with a question word and a helper verb ("where does …") (`app/lane.py:31`, `app/lane.py:178-194`). Action-lane order: a plan from word tables and each tool's name and first description sentence, checked in fixed order (capability question, feedback, setting, arithmetic, job run, calendar, memory delete/edit/save, workflow or schedule, artifact, image, web; `app/route.py:259-296`), negated clauses left out, none without an object; then tools whose name words the request uses (`app/surface.py:36-46`). No tool is removed.
- **M5 Recovery** reads only emptiness, `finish_reason`, a provider schema error (`app/action.py:326-332`) and, for the wrap-up, whether a call reached the endpoint; a complete reply with text is never re-asked for what it says. D, FQ, RC and DR are separate model calls whose output the deciding model reads; FC is a note.
- **M6 Answer**: the value after `ANSWER:` (label possibly in `*` or `_` emphasis; a backticked line read without backticks) on the last line starting with it, backticks and `*` trimmed from its edges, nothing else changed (`app/answer.py:5-20`).
- **M7 Packet** (`app/packet.py:204-242`): a ranking of this user's store, a 24 000-character budget, the first record in whatever its size. With an identifier of the request (12+ letters and figures, both present; `app/memory/retrieval.py:28`) carried by 3+ records: those records and the pins, by date (`app/packet.py:82-87`); else a leading thread of code-linked records, or two anchored ones, with records sharing their values; else the top records (three with no anchor in the store). On the records lane a nickname a short record gives a full name of the request, held by ≤24 records, is also a ranking term (`app/memory/retrieval.py:308-322`, `app/memory/retrieval.py:370-372`). Then records reached through shared values, two hops; ≤60 records. Records are chosen and ordered, never edited. On deciding turns the packet is in the platform memory format, "Relevant memory context for this turn:" then `{"longTerm": {"memories": [...]}}`, one JSON object per record: mark, pair id when handed out, timestamp, user and assistant text trimmed (`app/packet.py:258-273`).
- **M8 Advisory blocks** between packet and request, each under a header saying what it is. Records lane: stored conversations holding each distinctive term, by mark or pair id, plus M48's lines (`app/memory/coverage.py:126-143`); sentences stating a figure grouped by shared codes, not for a packet built around an identifier or thread (`app/records.py:433-435`). Action lane: ≤4 records of ≤1500 characters holding words the request quotes, again, by date (`app/action.py:364-372`); for a disposable-note request (M52) instead, when it uses a nickname a short stored conversation gives, every stored conversation of ≤600 characters naming it, ≤8, each with its own pair id, by date (`app/action.py:56-59`, `app/action.py:375-392`, `app/action.py:577-580`).
- **M9 Memory reads.** Records lane (R1, R3, P, Q): posted to the endpoint without RA, in `tool_calls` when they cross; the loop gets this harness's own store read, marked `served_by` (`app/records.py:573-579`); R1's hits become pins; a call naming a `pairIds`, `pair_id` or `subject_id` the user's store lacks is not posted and gets `UNHELD_IDS_NOTE` (`app/tools.py:222-234`). Action lane: read here, not posted, not in `tool_calls` (`app/action.py:660-663`). Empty input reads nothing and says so. ## 5. Fixed properties

- `final_text` and `answer` are model text, outer whitespace removed, M22 and M24 applied; nothing else is written, cut, joined or re-worded.
- No reply is chosen among others by what it says; no stage is re-asked for what its reply says (M5). After FQ's or FC's note the earlier reply ships only when the next is empty; after RC's or DR's, A1 replies or calls again.
- Every turn of R1, R3/R4, DC, P, Q, FC and A1/A2 carries the whole catalog (M3). The host never posts a held call on its own, never returns an earlier result as new (M1), never reports an unsent call as sent or a refused one as executed (M14).
- An unsent call (unreadable, outside the catalog, failed schema, unheld ids, held by RA, AC or DK, out of time) gets a note as its result and is logged `blocked_before_execution` (`app/records.py:559-602`, `app/action.py:656-689`); R1 drops unsendable calls; a nameless call is logged, not run (`app/llm.py:133`). These host checks read neither the request's words nor the case identifier.
