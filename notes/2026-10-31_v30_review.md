dan0l v29 and v30 were released on 2026-10-30 22:17 and 2026-10-31 00:52 UTC (released/dan0l-v29_336015f5, released/dan0l-v30_95534e25; v30 artifact sha256 29cf12e6…). Both trees are dated 2026-10-28, before v5 existed. This note reads the code and the public scores only; no model was called.

## What v29 and v30 changed from v28

v29, 15 files, mostly polish:
- Lane choice reads more forms of asking ("put … in order", "add up …", a later "what is …" clause; narrated "I updated …" is not a write request).
- Nicknames: retrieval and the coverage notes map a one-word name to the full name and back; `search_memories` finds a record by its own id.
- Action lane: the kind note also follows the message; two new kinds (tool preferences, building a workflow); about 15 tool-guide notes reworded; a world-now question gets no result verdict; a "named records" block for deleting a disposable note.
- Topic path: "do the records agree?" reads the two latest notes and answers "X ; Y ; disagree"; status and next-step values in the note's own words, ordinary misspellings corrected (also a spelling line in the final check for next-step requests).
- No-record wording for a trip leg or a partial payment; the follow-up rewrite keeps every sentence for those.
- Search passes: every text they looked up is shown once more, together.
- Money to the cent with its unit word; no-break spaces written as plain spaces.

v30, one change, in the program path (`short.py`):
- The order pass and the "self-marked changes last" reordering are gone. Notes are shown oldest first with their filing day, ties broken by pair_id (`memory/people.py:by_date`).
- `CHAIN_NOTE` asks to read them as one sequence: a later note changes a value or brings one back; a note calling an entry a mistake undoes it and what held before holds again; a suggestion holds only once it went ahead; a date written in the note beats its filing day; give the current value once.
- The shared draft is asked with the asking sentence alone, so reworded twins get the same draft.
