# 2026-11-02 — DrPresident v22's routing under bench v15 (mock model, no paid calls)

**Method.** DrPresident v22 (`released/DrPresident-v22_eeb26552`) ran through the real local scorer in its own mock
mode: `HARNESS_MOCK_MODEL=1` makes every model call return "Mock reply. ANSWER: mock", and embeddings are off.
- Every request was served exactly as the scorer serves it, and DrPresident's real code chose its lane and path.
  Scores are meaningless; only the routing is read.
- Seeds: the three s45 seeds, once at bench 14 (scorer .cache/dittobench-api) and once at bench 15.
- The bench-15 scorer was built by `tools/build_scorer_rev.sh` from ditto-subnet aeeccbb6, which includes the v15
  contract a131ed2.
- Script: `practice/gates/run_drp22_mock.sh`. Comparison: `practice/gates/route_v14_v15.py`.
- Served questions are deterministic per seed (244 of 244 matched v8's run of the same seed word for word), so
  v14 and v15 requests pair exactly except for the shifted dates.

- A "real move" means the lane name or path changed, counted over pairs with at least 0.9 text similarity.
- About 100 other requests per seed changed only the lane's reason label, keeping the same lane and path.
- About 57 tool prompts per seed are drawn differently at v15, so they cannot be paired. All of them stay in the
  action lane at both versions.
- The program path and the topic path (78 per seed) did not move.

**All 30 real moves go one way: a memory question leaves the records lane for the action lane.** There the model
sees the full ~235-tool menu instead of the user's records path.
- 22 balance and remaining-amount questions, to `action:imperative-setter`: "What is currently owed on X's
  account?", "How many nights / hours / seats / licences / percentage points remain for Y?".
- 4 questions, the whole news-subscription group on seed 5451 (3 rewordings and the counterfactual), to
  `action:imperative`. They move together, so no new split, but all four are answered in the wrong lane.
- 4 questions about figures quoted from a pasted footer or extract, or "what's left to pay … after the correction",
  to `action:read-capability`.

**Cause: tool-name vocabulary.** `lane.classify` builds read and write word sets from the tool names
(`vocabulary(tools)`). A short framing sentence before the question counts as an instruction when any of its words
matches a tool word. The 200 connectors add everyday words to that vocabulary. Found by adding v15 tools one at a
time to the v14 catalog (`classify` alone):

| framing sentence | single connector that flips it | shared word |
|---|---|---|
| "Sorting out where things stand." | `bamboohr_whos_out` | out |
| "Quick bookkeeping question." | `metabase_run_question` | question |
| "Checking one of my accounts." | `plaid_list_accounts` | accounts |

The connectors are drawn per seed (200 of 277), so the set of framing sentences that flip changes from seed to
seed. Roughly 10 of 250 memory questions per seed (4%) leave the records lane.

**With the connectors filtered out, the menu equals v14's.** v15 builds its catalog as `v13SeededCatalog(seed)`
(the v14 catalog, same function and seed) with the seed's 200 connectors spliced in (`catalog/v15.go`). On all
three seeds every v15 request carried exactly 200 names that v14 never had. Removing them left the v14 list,
same names and same order, on every paired request (293, 290 and 292). Script: `practice/gates/toolset_v14_v15.py`.
So a filter restores v14's routing input and the deciding model's menu. Three things still differ at v15:
- about 57 tool prompts per seed, and the 6–11 background notes their cases leave in memory;
- grading adds the atomic-value floor;
- the dataset dates move a month later.

**Not measured yet.** What these questions score in the action lane with a real model; it may still answer from
the packet, or call a connector. dan0l v30 and our v8 build their lane vocabulary the same way (dan0l lineage), so
the same exposure is likely there. That has not been checked: v8 has no mock mode.

## Screening rehearsal of drp22v15 (2026-11-02)

Package `practice/submission_drp22v15.tgz`, sha256 b7798af1…. It ships `DECLARATION.md` (DrPresident's, with our
row on top) and `PROVENANCE.md`. Scripts: `practice/gates/screen_drp22v15.sh`, `probe_drp22v15.sh`,
`l1_drp22v15.sh`.

**Pack, `ditto verify`, static scan:**
- `ditto verify` PASS, 37 files.
- Against the released DrPresident v22, 11 changed lines. No malicious or fingerprint lead. The 3
  numeric-candidate leads and the generator n-gram lead (`app/thint.py`) are inherited.

**Probe battery** (screener's own zero-token battery, bench 15):
- 62 probe calls on each of our build and the released v22: I2, I3, I4, I6, I7 and I8 items.
- **0 leads on both**, including the I7 items (unexpected tool, no-call respected, pinned choice, sticky veto).
- Setup gotcha: on this machine `~/.docker/config.json` sets the WSL proxy, which `docker run` copies into every
  container. The sandbox gateway's health check then goes to the proxy and fails ("harness never became healthy",
  released v22 included). The script runs the probe with `DOCKER_CONFIG` pointing to a config with no proxies
  (buildx kept), and passes `prepare --keep` so the battery finds the harness running.

**Lineage:** against our horizon v7 (parent) the scope is full ("diff-too-large": 28 files, 3,813 lines), because
the whole code base changes.

**L1** (production reviewer, full scope with the lineage packet):
- Cost: **$3.96** ($8.8593 → $4.8996). Earlier diff-scoped L1s cost $0.5–0.9; full scope reads everything.
- Result: risk **medium**, category benchmark_emulation, clearance_certified true, no finding. 48 notes.
- Two concern families recur:
  1. **Our filter**, about 15 notes on `app/available.py:18/22` and `app/agent.py:129`, confidence 0.75–0.84,
     "mandatory_contract_failure / user_isolation_correctness". The reviewer's point: the filter removes supplied
     tools "solely from description wording … without consulting live availability", so a connector that is
     actually linked in some workspace would be suppressed (I7). The PROVENANCE's W4 reading did not settle it.
  2. **Inherited from DrPresident:** the program path's reading rules at `app/short.py:60` (change history,
     chronology, lists, plans, roles, values), flagged as an I5 "family compiler" concern, confidence 0.99.
     DrPresident v22 cleared screening with this code; a full-scope review of the same code raises it again.
- Takeaway: the description-only test is the weak point. Options are to keep connectors out of routing only
  (menu unchanged); to keep a connector whose app the request names; or to get the operator's word on W4 before
  relying on it.
