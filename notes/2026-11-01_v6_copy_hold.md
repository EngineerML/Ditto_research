## The copy check

- **What it compares:** a lexical fingerprint of the code, with the starter kit subtracted, against every
  earlier submission by another owner. It holds at Jaccard ≥ 0.75, or at containment ≥ 0.95 in the
  padding direction. Score proximity plays no part.
- **What it skips:** the owner's own versions (same hotkey or coldkey).
- **Orsentra:** v13 → v16 → v17 is one owner's line, and its code matched no other owner's earlier code
  above the bars. Its source is not public, so how it was built can't be checked.
- **v6:** it is v30 with small changes, so it matched dan0l's line. The reason recorded: Jaccard 0.801,
  containment 0.859, line 0.828 / 0.909, structural 0.906 / 0.964, prompt 0.852 / 0.970.
  - The nearest earlier match was mvkdata v3 (8e3b03e6, uploaded 2026-10-28 21:50, unreleased).
  - The hold was re-pointed to the earliest artifact in the cluster: dan0l v28 (b4b99c40), a published
    release.

## Why the release did not withdraw the hold

A published release withdraws a hold only if it is in `published_before`. That list is built from
`eligible` alone, which holds one representative row per owner (scoring_gate.py ~773). When v6 was scored
(2026-10-31 12:01), dan0l's representative row was v31 (f4c92f11). v31 was finalized 2026-10-30 23:35
and is still embargoed. dan0l v28, v29 and v30 were public but absent from that list, so nothing could
withdraw the match against mvkdata v3.

Attribution then reads the full history (`eligible_history`) and named v28, the published release. The
hold therefore names a published artifact as the source, which the subnet owner has said is permitted to
build on. The withdrawal and the attribution read different row sets.

To clear, both Jaccards must be under 0.75 against every earlier agent by another owner. dan0l v31 and
mvkdata v3 aren't public; v30 stands in for them.
- **Replacing code:** replacing a share x of v30's content gives a Jaccard of about (1 − x)/(1 + x). That
  is under 0.75 at x ≈ 15 % and about 0.70 at x ≈ 18 %.
- **Adding code:** this doesn't help. Adding a third more code brings the Jaccard to 0.75, but then our
  residual is ≥ 1.15× v30's and still about 99 % contains it, so the padding arm fires.
- **Cosmetic changes:** these don't help either. The normalized source hash strips comments and
  whitespace, and the structural channel reads the AST.
