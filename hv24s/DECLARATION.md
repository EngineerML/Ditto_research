**What the host never does on the served path.** It computes no answer value, compares no reply with a draft, retries on no
disagreement, overwrites or substitutes no well-formed reply, parses no case-file line into steps or operands, and forces no tool
or removes one from the catalog (calls it does not send, such as an unknown tool or an id the store does not hold, are listed
under the base's section). Every shipped text and ANSWER is the deciding model's own; the only fallback is W7 (`TopicPath.answer`: the
same request's own draft when the deciding call returned no text).

**Same question: the key over case files.** `same_file` hashes the values on the lines joined to the ids a question names, in any column order and under any file code, to tell whether two case files hold the same facts (`app/short.py:726`, used at `app/agent.py:165`). Only the key is used: the repeat call sees the earlier question, the model's earlier reply and the new message, and no lines of the file (`SAME_FACTS_LINE`), since lines drew the model into working the answer out again. It resends the reply or says DIFFERENT, and the model writes what ships (policy clarification of 2026-10-29: content-keyed reuse as prompt text).

**Same question: the key.** `note_words` takes the set of words and figures in the notes under the question's identifier, without
the identifier; two requests count as the same when those sets share at least 99% of their words, the codes and figures they
name match and the asking sentences are at least 90% alike after typo reading. No line, field or step is parsed, and nothing read
by the key reaches the model. A request to do something never takes this path.

## 2. Served path

### 2.1 Entry

- `Dockerfile:8` starts `app.main:app`, one worker. `POST /seed` stores the user's pairs, subjects and links and embeds the pairs (M20; `app/main.py:46-58`). `POST /run` calls `CaseRunner.run` (`app/main.py:60-72`); an invalid body gets 400, a failed run 500, with the error text; bodies are ASCII JSON.
- SQLite store; every pair, subject, link and vector row is keyed by the user id (`app/store.py:11-51`). Of the request the host reads the case id, `system_prompt`, the message, the catalog, the tool endpoint, the user id and the relay URL (`app/protocol.py:25-32`); the case id goes only into tool endpoint bodies (`app/tools.py:157`) and logs. 285 s case deadline, one tool executor per case (`app/agent.py:119-123`).

### 2.2 Lane

Without a model the host ranks the user's stored conversations (`app/memory/retrieval.py:328-424`), finds the identifier focus (M7) and the request kinds (M52), and classifies the main clause (M44) with the catalog's tool names (M4) (`app/agent.py:126-136`). The first rule that holds moves an action-lane request to the records lane (`app/agent.py:137-152`):

| reason | when |
|---|---|
| `identifier` | lane reason `live`, and an identifier focus |
| `identifier-held` | an identifier focus, and AT with its fetching test read per sentence |
| `own-records` | reason `live`; asks, names nothing to be done, no outside source, no capitalised name the store lacks; a name, address, code or quoted phrase of it, or the noun of "my/our <noun>", is in the store (`app/lane.py:308-350`) |
| `identifier-read` | reason `default`; AT with "work" as a reading verb (`app/lane.py:38`); an identifier or hyphenated code (`app/store.py:54`) a ranked record holds (`app/packet.py:78-80`) |
| `topic` | no kind, no identifier focus, AT, a topic the store dwells on (M27) |
| `quoted` | no kind, AT, quoted words the store holds (`app/memory/retrieval.py:219-222`) |

A records-lane request with a kind is decided on the action lane, reason `guided` (M53, `app/agent.py:153-154`). The lane picks prompt and packet; every turn that may call tools gets the whole catalog (M3).

AT, the asking test (M25, `app/lane.py:364-370`): the request asks (a question, or a reading or speech verb such as list, find, tell, name, give; `app/lane.py:173-182`, `app/lane.py:383-384`), has no verb of doing (send, set, update, schedule, create, delete…; `app/lane.py:402-403`), names no outside source (web, online, internet, news, google, browse, "look it up"; `app/lane.py:54`), names no listed tool in full (memory tools, one-word and all-generic names aside; `app/lane.py:212-220`), and does not pair a fetching verb with a word of a listed non-memory reading tool's name, same word, singular or plural, or for 5+ letters and not a common word one edit away (`app/lane.py:387-399`); with an identifier focus only within one sentence (`app/lane.py:359-361`).

## 5. Fixed properties

- `final_text` and `answer` are model text, outer whitespace removed, M22 and M24 applied; nothing else is written, cut, joined or re-worded.
- No reply is chosen among others by what it says; no stage is re-asked for what its reply says (M5). After FQ's note the earlier reply ships only when the next is empty; after RC's or DR's, A1 replies or calls again.
- Every turn of R1, R3/R4, DC, P, Q and A1/A2 carries the whole catalog (M3). The host never posts a held call on its own, never returns an earlier result as new (M1), never reports an unsent call as sent or a refused one as executed (M14).
- An unsent call (unreadable, outside the catalog, failed schema, unheld ids, held by RA or AC, out of time) gets a note as its result and is logged `blocked_before_execution` (`app/records.py:578-624`, `app/action.py:587-629`); R1 drops unsendable calls; a nameless call is logged, not run (`app/llm.py:133`). These host checks read neither the request's words nor the case identifier.
