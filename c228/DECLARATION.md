# Pipeline declaration

## Changes in this submission (overhorizoner, built on the released crown-v228)

This is crown-v228's declaration, kept as shipped. `PROVENANCE.md` lists our changes to it. None of them adds a model call or a stage:

- **Code mechanisms (holds, view inputs):**
  - In the tied-names view (`app/evidence.py`, stage V): initials ties, a list-answer note, a 28-note cap, and a code-read list headed "not checked; the notes decide".
  - In the action lane (`app/action.py`, `app/tracked.py`, `app/jobs.py`): three first-call holds that the model can override by sending the call again (already tracked, list before create, run not finished).
  - In polling (`app/tools.py`): a running job's status read goes out again with no repeat check.
- **A name repair:** tool-name trimming in `app/llm.py`.
- **Notes:** the open-the-page note for incident and pricing requests (`app/action.py`).

The line numbers in the sections below point to crown-v228's released layout; the files named above have moved by a few lines.

---

Every model call and every host step on the served path. §0 and §1 give exact lines; §2 to §6 name the file and the symbol.
No model weights or opaque components; the only model is hosted and called over HTTP.
§0 is the review map, §1 the decision paths. Stages (R1, P, A1, …) are in §4, host mechanisms M1–M72 in §5.

## 0. Review map: what this source changes against dan0l v30, and what the host never does

This fork is built on the publicly released dan0l v30 source (agent `95534e25`; reuse of released king source is permitted). `Dockerfile`, `requirements.txt` and every source file not named here are byte for byte v30's. These differ: `app/action.py`, `app/agent.py`, `app/config.py`, `app/guide_records.py`, `app/guide_tools.py`, `app/lane.py`, `app/llm.py`, `app/memory/deliberation.py`, `app/memory/finder.py`, `app/memory/retrieval.py`, `app/memory/topic.py`, `app/packet.py`, `app/records.py`, `app/request_kinds.py`, `app/route.py`, `app/short.py`, `app/tools.py`, `app/typography.py`, and this file. `app/connectors.py` is new. `app/evidence.py`, `app/view_guide.py`, `app/memory/view_people.py`, `app/guide_spelling.py` and `app/english_words.py` are new here and reuse the released Hades v26 source (row 25). Four mechanisms were read in Tessellate v2 as released (agent `19c596b5`): later turns of a conversation seated after the record they continue (row 27), cue words for a name a person is called (row 28), a view for a contact detail asked of a quoted project (row 25), and the `**ANSWER: value**` form (row 23); the code for them was written here. A fifth idea read there, showing records as `Full Name (word)`, was not taken: records stay unchanged, and row 29 carries the tie as a key beside the record instead.

The host never: writes or rewrites a reply beyond the typography of M22 and M24; chooses a reply among others by what it says; compares the values of drafts; works out an answer value and places it in a prompt; changes a tool's arguments; or holds a model-selected call on a model check, except RA's check of an exact repeat, which the deciding model can overrule by sending the call again. It reads the words of a model's text in these places only, each listed in §1.3: SQ's control word; the verdict words of RA, RC and RV, and RC's next sentence; the calls a DR draft proposes; the full names in H's reply; whether a draft has an `ANSWER` line with a value, which decides whether a draft check runs and whether L's draft is shown; and the `ANSWER` line of the reply that ships, which fills `answer` (§1.4). SQ has no tools (row 12); every other deciding turn loses only connector tools (row 1). Advisory calls reach the deciding model as prompt text.

## 3. Served path

### 3.1 Entry

- `Dockerfile` starts `app.main:app`, one worker. `POST /seed` stores the user's pairs, subjects and links and embeds the pairs (M20; `app/main.py`). `POST /run` calls `CaseRunner.run` (`app/main.py`); an invalid body gets 400, a failed run 500, with the error text; bodies are ASCII JSON.
- SQLite store; every pair, subject, link and vector row is keyed by the user id (`app/store.py`). Of the request the host reads the case id, `system_prompt`, the message, the catalog, the tool endpoint, the user id and the relay URL (`app/protocol.py`); the case id goes only into tool endpoint bodies (`app/tools.py`) and logs. 285 s case deadline, one tool executor per case (`app/agent.py`).

### 3.2 Lane

Without a model the host ranks the user's stored conversations (`app/memory/retrieval.py`), finds the identifier focus (M7) and the request kinds (M52), and classifies the main clause (M44) with the catalog's tool names (M4) (`app/agent.py`). The first rule that holds moves an action-lane request to the records lane (`app/agent.py`):

| reason | when |
|---|---|
| `identifier` | lane reason `live`, and an identifier focus |
| `identifier-held` | an identifier focus, and AT with its fetching test read per sentence |
| `own-records` | reason `live`; asks, names nothing to be done, no outside source, no capitalised name the store lacks; a name, address, code or quoted phrase of it, or the noun of "my/our <noun>", is in the store (`app/lane.py`) |
| `identifier-read` | reason `default`; AT with "work" as a reading verb (`app/lane.py`); an identifier or hyphenated code (`app/store.py`) a ranked record holds (`app/packet.py`) |
| `own-topic` | lane reason `default`, `live` or `read-capability`; passes the asking test; names a topic the user's own records dwell on (`app/agent.py`) |

A records-lane request with a kind is decided on the action lane, reason `guided` (M53, `app/agent.py`). After these rules, a request with no kind, not of reason `statement`, with no verb of doing (`effecting`), that a view shows notes for takes the records lane with reason `evidence`, whatever its reason was (M72). ### 3.3 Records lane

- First SQ (M65), only for a records-lane request not of reason `statement`, with a focus token, no kind and no verb of doing (`effecting`); it ends the request when it replies with text other than the word DIFFERENT alone.

A short path ending with reply text answers; else its calls go on (M54).
- Stages (`app/records.py`): R1; the packet (M7) with meaning order (M20; `app/agent.py`); advisory blocks (M8); T or S, then N; the loop R3 with D/DC (M17), RA (M1); closing turn R4.

### 3.4 Action lane

Packet (M7) without embeddings, M34's block, catalog in route order (M4), M52's notes; A1/A2 with RC, DR, RR/RV, RA (`app/agent.py`, `app/action.py`).

### 3.5 Response

- `final_text`: the text of the completion that ended the deciding loop, outer whitespace removed (`app/agent.py`); if R3's loop ends with no text, draft 1's when M17 ran (`app/records.py`). `answer`: the value after `ANSWER:` on its last line starting with it (M6; `app/records.py`, `app/action.py`). - `tool_calls`: calls that crossed to the tool endpoint and were not refused with a 4xx (M14). The wire body holds `final_text`, `tool_calls`, `prompt_tokens`, `output_tokens`, `latency_ms` and, when present, `answer` trimmed, nothing else (`app/protocol.py`).

## 6. Fixed properties

- `final_text` and `answer` are model text, outer whitespace removed, M22 and M24 applied; nothing else is written, cut, joined or re-worded.
- No reply is chosen among others by what it says; no deciding stage is re-asked for what its reply says (M5); a draft check runs only for a first draft with an `ANSWER` line with a value, and its reply is prompt text; SQ's reply is read only for being empty, cut or the word DIFFERENT alone, a word the system text gives the model for saying the new message names another step, id or subject, asks for another value, or asks to look it up again (M65); a search pass is re-asked only for a reply with no call and no usable text (M70). After FC's note the earlier reply ships only when the next is empty; after RC's or DR's, A1 replies or calls again.
- Every turn of R3/R4, DC, P, Q, V, FC and A1/A2 carries the whole catalog (M3), less the unlinked connector tools and the connector tools of apps the request does not name (W4). The host never posts a held call on its own, never returns an earlier result as new (M1), never reports an unsent call as sent or a refused one as executed (M14).
- An unsent call (unreadable, outside the catalog, failed schema, held by RA, out of time) gets a note as its result and is logged `blocked_before_execution` (`app/records.py`, `app/action.py`); R1 drops unsendable calls; a nameless call is logged, not run (`app/llm.py`). The mechanical checks read neither the request's words nor the case identifier; RA, a model call, gets the request in its prompt.
