# Pipeline declaration

Every model call and every host step on the served path, with the lines that show them.
No model weights or opaque components; the only model is hosted and called over HTTP.

## 1. Served path

- `Dockerfile:8` starts `app.main:app`. `POST /run` (`app/main.py:68`) calls `CaseRunner.run` (`app/agent.py:109`) with a
  case deadline of 285 s (`app/config.py:28`). One executor serves the whole case (`app/agent.py:115`).
- Without a model, the host ranks the user's stored conversations (`app/memory/retrieval.py:328`) and picks a lane from the request's words and its
  catalog's tool names (`app/agent.py:118`, M4); a live-information cue goes to the records lane when an identifier in
  the request is carried by at least three of the user's records (`app/agent.py:126-127`), or when the request asks (and does not ask for
  something to be done) about what the user's own records hold, names no outside source and no name the records lack (`app/agent.py:130-131`, `app/lane.py:340-347`). The lane chooses the prompt and the
  record packet (`app/agent.py:134-153`) and takes no tool away (M3).
- A request whose identifier is carried by at least three of the user's records goes to the records lane, whatever made it read as a request to act, when it is a question about those records: it asks (a question, or a reading or speech verb such as list, find, tell, name or give), has no verb of doing something (the action words outside the reading verbs: send, set, update, schedule, create, delete…), names no outside source (web, online, internet, news, google, browse, "look it up"), names no listed tool by its full name, and does not pair a fetching verb (search, find, look, fetch, pull, open, grab, read, research, see, browse, google) with a word of the name of a listed reading tool other than the memory tools: the same word in the singular or plural, or, for a word of five letters or more that is not a common English word, one edit away, both inside one sentence of the request, so that a fetching verb in one sentence and a tool's word in another do not pair (`app/agent.py:128`, `app/agent.py:80`, `app/lane.py:356-358`, `app/lane.py:361-366`, `app/lane.py:369-376`, `app/lane.py:379-380`, `app/lane.py:383-384`, `app/lane.py:387-395`, `app/lane.py:398-399`, `app/lane.py:151-164`, `app/lane.py:35`, `app/lane.py:36`, `app/lane.py:38`, M25).
- A request read as asking for something to be done only because none of the router's words were found in it (lane reason `default`) goes to the records lane as `identifier-read` when it passes the same test of M25 with the verb "work" (as in "work out") counted as a reading verb and a fetching verb paired with a reading tool's word anywhere in the request, and names an identifier or a reference code (letters and digits joined by hyphens, as M7 finds them) that at least one of the user's ranked records holds (`app/agent.py:132-133`, `app/lane.py:37`, `app/lane.py:356-358`, `app/lane.py:361-366`, `app/packet.py:77-79`, M41).
- In the records lane, before its stages, a short path may answer a request that passes the same test and is not read as a statement (`app/agent.py:80`, `app/agent.py:134`, `app/agent.py:78-95`). A short path chooses a smaller set of the user's records (for programs it also runs the order pass O) and writes one user message; its deciding call runs in the records lane's own deciding loop, with the request's whole catalog and `calculate` on every turn, every call executed as R3 executes it (`app/short.py:156-161`, `app/records.py:422-575`, `app/agent.py:134`). When that loop ends without reply text, the records lane runs its own stages; calls already made stay in `tool_calls` (`app/agent.py:136-145`).
  Programs (M26): a request naming an identifier that every one of its focus records carries, those records holding at most 30 000 characters together and none of them more than 2000 (`app/agent.py:89`, `app/short.py:67-68`, `app/short.py:46`, `app/short.py:71-75`), gets the order pass O and the deciding call P over those records only, whole, with their dates, copies of one statement side by side, after the statement of each group once, in O's order, without dates, when no statement is over 1000 characters (`app/short.py:85-89`, `app/short.py:111-120`, `app/short.py:149-153`, `app/short.py:218-222`, `app/short.py:164-165`). Shared draft SD: after O, one advisory call with no tools writes a draft answer from the same system text and the same user message as P's, the complete request included (`app/short.py:225`, `app/short.py:245-260`, `app/short.py:179-180`); it runs at P's effort, once more at `low` when empty, with up to 12000 tokens. Requests of this run from the same user over the same records whose asking part is the same (`asked_part`: the sentences ending in a question mark, or the longest sentence when none does; `app/memory/retrieval.py:81-89`) are rewordings of one question: the first of them writes the draft with its own complete message and the others reuse it, as rewordings already share one O reading; the key is the user, P's system text with the operator's prompt, the records as P shows them and the asking part (`app/short.py:221-225`, `app/short.py:230-234`). When the draft holds an `ANSWER` line with a value, every one of these requests, the first included, gets it in P's user message, before `Message:`, under `SHARED_DRAFT_NOTE` ("A draft reply, written once from these same notes for the question …; it has not been checked, and the notes decide wherever they differ: … Check the draft against the notes, then reply to the message as asked at the start.", `app/short.py:58`, `app/short.py:226-228`); P decides for itself over its complete records and its own complete message at its usual effort, and the draft's text never ships. The host reads only whether the draft holds such a line (`app/short.py:253`); a later rewording waits for the draft only while more than 60 s of its own time are left, and without it decides as before (`app/short.py:59`, `app/short.py:236-243`); a draft that fails or holds no such line is not kept, and the next rewording writes one (`app/short.py:256-258`). Nothing passes between users.
  Topic (M27, M28): a request naming no such identifier, holding no quoted text and no full name that the user's short records hold, whose topic phrase the records dwell on (`app/short.py:426-449`, `app/memory/topic.py:92-111`), gets the advisory call L over the latest passages (M33) and the deciding call Q: first a copy of the paragraphs that hold the phrase, each on its own under the mark and date of its record, then the chosen records whole (`app/short.py:426-449`, `app/short.py:381-392`, `app/short.py:271-281`); when the request names a nickname that the user's short records give in quotes, and at least two chosen records of several paragraphs name it, only the chosen records that name it go on (`app/short.py:447`, `app/short.py:464-475`); a request asking for an email or address first gets the advisory call H, then also the records of the person H names, or, when H names no one the short records name in full, of the people the chosen records name in full (`app/short.py:387-388`, `app/short.py:404-408`, `app/short.py:371-379`).
- In the records lane, when no short path took a request that names no identifier its records carry, the topic path of M27 and M28 may still answer it, with the same calls and records, and the records lane runs its own stages when that path ends without reply text: a request asking for a contact detail the user keeps (lane reason `stored-detail`, M4) that does not pass M25's asking test (`app/agent.py:135`, `app/agent.py:97-107`, M46).
- The response (`app/agent.py:163`): `final_text` is one completion's text with outer whitespace removed; `answer` is the text
  after `ANSWER:` on the last line of that same completion that starts with it, in any letter case, with backticks and `*` trimmed from its two edges (`app/answer.py:5-6`,
  `app/records.py:574`, `app/action.py:659`); in both, the hyphen U+2010 and the non-breaking hyphen U+2011 are written as the plain hyphen `-`
  where the table of M22 says so, a bold pair `**…**` outside code loses its two markers, except around a bare figure followed by a full stop or comma with more text after it (M24), and nothing else changes (M22, M24); `tool_calls` is the executor's list of calls that crossed to the tool
  endpoint and were not refused with a 4xx (`app/tools.py:163`, `app/tools.py:173`, M14); the wire body holds `final_text`, `tool_calls`, `prompt_tokens`, `output_tokens`, `latency_ms` and, when there is
  one, `answer`, and nothing else (`app/protocol.py:51-61`).

## 2. Model calls

All go through `OpenAICompatLLM.chat` (`app/llm.py:242`) on the request's relay URL (`app/agent.py:68-69`), else the configured endpoint
(`app/agent.py:70-72`, `app/llm.py:343-361`). Payload: model (`app/config.py:66`), messages, tools with `tool_choice` `auto` when
any, `temperature` 0 and `seed` 42 (`app/config.py:42-43`), reasoning effort and `max_tokens` (`app/llm.py:243-256`); only D's drafts set
`temperature` 0.7, `seed` 43/44 (configured seed + index − 1) and `tool_choice` `none` (`app/llm.py:243`, `app/llm.py:254`,
`app/memory/deliberation.py:71-72`); DR's drafts (M50) set `temperature` 0.8 and `seed` 101/202 and keep A1's `tool_choice` (`app/action.py:81-82`, `app/action.py:503`). No `n`, `best_of` or field outside the relay's forwarded and pinned lists. A call the model made is repeated to its later turns as the model wrote it, except that an argument with an empty name is left out of that copy, since the provider refuses a conversation that repeats one; the endpoint and `tool_calls` get the call unchanged (`app/action.py:334-338`). A draft is sent once and never again (`app/llm.py:312`, `app/llm.py:329-330`); any other call is sent again only on a transport outcome:
failed or timed-out connection (`app/llm.py:277-290`), 408/409/425/429/5xx (`app/llm.py:320-328`), a 200 that is not a completion
(`app/llm.py:299-303`); 429 or 503 with `Retry-After` is waited out, ≤5 s × 30 (`app/llm.py:312-319`); after a timeout, 0.4 of `max_tokens`,
never under 1200 (`app/llm.py:287-288`). A completion is returned as it came (`app/llm.py:305-309`); text parts are joined, a nameless call
skipped (`app/llm.py:126-134`). All usage, failed calls' included, enters the case tally before the reply is read (R1 `app/records.py:182-185`, S `app/records.py:289-292`, N `app/records.py:330-334`, T `app/records.py:351-358`, R3 `app/records.py:450-454`, D `app/memory/deliberation.py:87-99`, A `app/action.py:558-562`, RA `app/action.py:132-135`, RC `app/action.py:169-172`, O, SD and H `app/short.py:129-135`; P and Q at R3's site).

## 4. Fixed properties

- `final_text` and `answer` are the model's text with outer whitespace removed, the two hyphen characters of M22 written as the
  plain hyphen and the bold markers M24 removes removed; nothing else is written, cut, joined or re-worded (§1).
- No reply is chosen among others by what it says, and no stage is asked again because of what its reply says (M5, M17, M35: RC is armed by a reply's shape, its verdict is a separate model's, and the deciding model may keep its reply; M32: FQ is armed by DC's reply's shape, and the reply after its note gives way to DC's only when it is empty; M36: the final check is armed by the path and the reply's shape, and the reply after its note gives way to the one before only when it is empty); RA gets
  one reminder when its first word is neither `SEND` nor `HOLD`.
- Every turn of R1, R3/R4, DC, P, Q and A1/A2, the closing turns included, carries the whole catalog (M3). The calls without tools
  are RA (M2), RC (M35), RR (M30), AC (M37), RV (M38), L (M33), FQ (M32) and the passes O, T, N and H, whose text is never the reply; DR's drafts (M50) are offered A1's list, their calls are never posted and their text is never the reply.
- A held call is not posted by the host on its own, and an earlier result is not returned as a new one (M1).
- An unsent call (unparsable, outside the catalog, failed schema, held by RA or after AC, out of time) gets a note as its result in R3/R4, P, Q
  and A1/A2 and is logged `blocked_before_execution` (M12; `app/action.py:609-622`, `app/records.py:524-551`,
  `app/action.py:629-631`, `app/records.py:558-560`), as are a draft's calls; R1 drops only unsendable calls, logs an RA hold (`app/records.py:223`);
  a nameless call is logged, not run (`app/llm.py:133`). None of these checks reads the request's words or case id.
- Of the request the host reads the case id, the operator's `system_prompt`, the user's message, the catalog, the tool endpoint, the user id and the
  relay URL (`app/protocol.py:25-32`); the case id goes only into the body sent to the tool endpoint (`app/tools.py:146`) and into log lines.
- A call that was not sent is not reported as sent, and a refused call is not reported as executed (M14).

- DK (M42) is also a call without tools, and its text is never the reply; a call it holds gets `DUPLICATE_CHECK_NOTE` as its result in A1 and is logged `blocked_before_execution` (`app/action.py:624-626`).
